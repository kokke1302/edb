# アプリ設計詳細

## UI/UX設計

アプリの画面構成やユーザーインターフェース、操作感をデザインする。
本セクションでは、FlutterのUIコンポーネントの名称を用いて説明する場合がある。
このドキュメントは、英語学習支援アプリの各機能を、コーディング時に困らない程度の具体性で詳細化することを目的とする。

### 全画面共通要素

- AppBar:
  - 画面上部に表示されるバー。
  - Leading: ハンバーガーメニューアイコン（IconButton）。左隅に配置され、タップするとDrawerが開く。
  - Title: 現在の画面のタイトル（例: 翻訳モード、単語帳）。

- Drawer:
  - AppBarのハンバーガーメニューアイコンをタップすると、画面左端からスライドして表示されるサイドメニュー。
  - ヘッダー: "保存済みの英文"
  - メニューアイテム:
    - 保存された英文のリスト: 各アイテムをタップすると、翻訳モードでその英文が復元される。
    - 保存解除（削除）オプション: リストアイテムの横に削除アイコンなどを配置。
    - 設定: 設定画面への遷移。
    - ヘルプ: ヘルプ画面への遷移。

- BottomNavigationBar:
  - 画面下部に表示されるナビゲーション。
  - タップすることで、対応するモードの画面に遷移する。
  - アイテム:
    - 翻訳モードへの切り替えアイコン/ラベル。
    - 単語帳モードへの切り替えアイコン/ラベル。

### 翻訳モード画面

- 英文入力エリア:
  - 画面上部。
  - 複数行入力可能なTextField。
  - テキスト入力エリアをタップするとキーボードが起動する。
  - 入力エリア内には「タップでキーボードが起動します」という旨の薄いテキストを表示する。
  - クリアボタン、ペーストボタンなどを入力フィールドの左下に常設する。

- 単語ブロック表示エリア:
  - 画面下部。
  - 入力された英文を解析し、単語ごとに「単語ブロック」として表示する。
  - Wrapウィジェットなどを用いて、単語ブロックは横並びに配置され、画面幅に応じて自動で改行される。
  - 各単語ブロックは、上段に英単語、下段に日本語訳を表示するスペースを持つ。
  - 日本語訳は、ユーザー辞書から取得した訳語が表示される。
  - スクロール機能：英文が画面に収まらない場合はSingleChildScrollViewなどで垂直スクロール可能にする。
  - 単語ブロックをタップすると「辞書機能」に遷移する。

- **右下**:
  - FloatingActionButtonを配置。
  - 「翻訳スタート」と「英文保存」のトリガーをボタンとして表示する。

### 辞書機能（VocabularyInputSheet）

- 単語ブロックをタップすると表示されるshowModalBottomSheetのシート。
- シート内には、以下の情報が順にリストアップされる。
  - 英単語表示部:
    - 英単語をTextウィジェットで表示する。
  - 訳語表示セクション:
    - 単語帳に登録された訳語と内部辞書の訳語が対象。
    - 英単語に対して表示する訳を一番上に持ってくる。
    - 次に単語帳に登録した訳、内部辞書の訳の順に表示される。
    - 各訳語はTextウィジェットで左揃えで表示し、右には「訳を表示するかどうか」（Switchウィジェット）と「単語帳へ登録済みかどうか」（Switchウィジェット）を配置する。
    - 単語帳に登録されている訳語の場合、その訳語に関連付けられたメモも小さめに表示する。
    - 訳語がなければ、このセクションは表示されない（詰める）。
  - オリジナル訳語セクション:
    - 「オリジナル」と薄いテキストを左揃えで表示する。
    - このセクション全体をタップ可能にし、タップすると「オリジナル登録フィールド」へ遷移する。

### オリジナル登録フィールド（OriginalEntryScreen）

- オリジナル訳語を単語帳に登録・編集するときの専用画面。
- 英単語表示/入力フィールド:
  - 単語帳入力画面から遷移してきた場合、英単語はTextウィジェットとして表示され、編集不可とする。
  - 単語帳モード画面から新規登録で遷移してきた場合、TextFieldウィジェットとして表示され、薄字で「英単語」と表示する。
- 訳語入力フィールド:
  - TextFieldウィジェット。
  - 薄字で「オリジナル」と表示する。
- メモ入力フィールド:
  - TextFieldウィジェット。
  - 薄字で「メモ」と表示する。
- 訳の表示可否スイッチ:
  - Switchウィジェット。
  - 初期状態ではoff（false）に設定する。
- 操作ボタン:
  - ElevatedButtonまたはTextButton。
  - 保存ボタン: 入力された情報を単語帳に登録または更新する。
  - キャンセルボタン: 画面を閉じ、前の画面に戻る。

### 単語帳モード画面

- **上部**: フィルタボタンと検索ボタンを横並びに配置し、データベースの単語を絞り込めるようにする。
- **データベース部**:
  - **上部**: カラムの最上部にはIconButton形式の+ボタンを配置し、タップすると「オリジナル登録フィールド」に遷移する。
  - **下部**: その下には、右に英語、左に訳語が表示されるカラム形式で単語リストをListViewなどで表示する。
- **右下**:
  - FloatingActionButtonを配置。
  - フィルタ、検索、新規単語登録のショートカットボタンを表示する。

## データ構造設計

辞書データ、保存する英文、ユーザー単語帳などのデータの持ち方を設計する。

### 英文データ (EnglishTextData)

アプリ内部で英文を管理するためのデータ構造。Sqfliteで管理。

| フィールド名 | 型 | 説明 |
| :---- | :---- | :---- |
| id | INTEGER | 主キー、自動インクリメント |
| original_text | TEXT | 元の英文全体 |
| parsed_words_json | TEXT | 解析された単語のリスト（JSON形式で保存） |
| created_at | TEXT | 保存日時 |
| updated_at | TEXT | 更新日時 |

parsed_words_json の内部構造例（トークン配列）:

<details><div>

```json
[  
  {  
    "word": "I",  
    "lookup_key": "i",  
    "resolved_translation": "私", // 最終的に表示される訳語。単語帳設定で非表示なら空文字列  
    "is_word": true // 単語である場合はtrue
  },  
  {  
    "word": ".",  
    "lookup_key": null,  
    "resolved_translation": null,  
    "is_word": false // 句読点であるためfalse  
  }  
  // ...  
]
```
</div></details>

### 単語帳データ (VocabularyEntry)

ユーザーが独自に登録した単語と訳を管理するためのデータ構造。Sqfliteで管理。

| フィールド名 | 型 | 説明 |
| :---- | :---- | :---- |
| id | INTEGER | 主キー、自動インクリメント |
| english_word | TEXT | 英単語（小文字で保存、ユニーク制約） |
| japanese_translation | TEXT | 日本語訳 |
| is_hidden | INTEGER | 訳を非表示にするかどうか (0: false, 1: true) |
| memo | TEXT | ユーザーメモ |
| created_at | TEXT | 登録日時 |
| updated_at | TEXT | 更新日時 |

### 内部辞書データ (InternalDictionary)

ejdict-hand のデータをアプリに組み込む際のデータ構造。Sqfliteで管理。

| フィールド名 | 型 | 説明 |
| :---- | :---- | :---- |
| id | INTEGER | 主キー |
| word | TEXT | 英単語（小文字で保存） |
| translation | TEXT | 日本語訳 |

## テキスト処理

1. 入力英文の取得: ユーザーが入力した英文（String）を取得。

2. 文の分割:
  - 入力された英文を、ピリオド (.)、疑問符 (?)、感嘆符 (!) のいずれかの後に、アルファベット以外の文字（スペース、改行など）が続く箇所で文に分割する。
  - これにより、複数の文からなる英文を個別の文として扱う。
  - 例: "Hello. How are you? I'm fine!" -> ["Hello.", " How are you?", " I'm fine!"]
  - 実装方針: DartのStringクラスのメソッドと正規表現（RegExp）を用いて実装する。

3. 各文のトークン配列生成:
  - 入力された英文を、辞書検索可能な個々の単語（トークン）に分解する。
  - 単語分割:
    - スペース（ ）と主要な句読点（., ,, !, ?, :, ;, ", ', (, ), [, ]など）で文字列を分割し、単語と句読点を独立したトークンとして扱う。
    - ハイフンやアポストロフィを含む単語（例: don't, well-known）は、初期段階では分割せず一つの単語として扱う。
    - 例: "Hello." -> ["Hello", "."]
    - 実装方針: DartのStringクラスのメソッドと正規表現（RegExp）を用いて実装する。
    - 各トークンに対して、それが単語であるか句読点であるかを判断し、is_word属性を設定する。

4. 小文字化と辞書検索キー生成:
  - 分割された各単語トークン（is_word: trueのトークン）に対し、辞書検索用のキーを生成する。
  - is_wordがtrueの単語トークンのみ、全て小文字に変換したものを検索キー（lookup_key）とする。
  - is_wordがfalseの句読点トークンは、lookup_keyをnullとする。
  - 例: Hello -> hello, Apple -> apple

5. トークンへの訳語割り当てフロー:
  - 上記処理で得られたトークン配列の各単語トークン（is_word: trueのトークン）に対して、訳語を決定する。この決定された訳語が、parsed_words_jsonのresolved_translationに格納される。
  - 単語帳(VocabularyEntry)を参照し、単語トークンのlookup_key（小文字化した英単語）を使用して、VocabularyEntryテーブルを検索する。
    - 見つかった場合:
      - 該当するVocabularyEntryのis_hiddenがtrue（1）の場合、resolved_translationは空文字列""とする。（ユーザーがその単語の訳を非表示に設定しているため）
      - is_hiddenがfalse（0）の場合、そのjapanese_translationを訳語として採用し、resolved_translationに格納する。
    - 見つからなかった場合:
      - ユーザー辞書に該当する単語が見つからなかった場合、resolved_translationは空文字列""とする。

6. 英文データ構造への変換:
   - 上記処理で得られた各トークンと検索キー、is_word属性、そして決定されたresolved_translationを、英文データのparsed_words_jsonフィールドに格納する形式に変換する。

## 表示ロジック設計

テキスト処理によって得られた英文データ(EnglishTextData)をもとに、トークンを単語ブロック、配列を文として表示する。

1. 英文データの取得: 翻訳モードで表示すべき英文データ(EnglishTextData)を取得する。

2. 単語ブロックの生成:
  - 英文データのparsed_words_jsonをパースし、各トークンをループ処理する。
  - 各トークンに対して、「単語ブロック」ウィジェットを生成する。

3. 訳語の表示:
  - 各単語ブロックの生成時に、トークンオブジェクトのresolved_translationの値を参照する。
  - is_wordがtrueの場合、resolved_translationがnullまたは空文字列でなければ、その値を単語ブロックの下段に表示する。
  - 句読点の場合: is_wordがfalseの場合、訳語は表示しない。

4. レイアウト調整:
  - 単語ブロックはFlexbox（FlutterのWrapウィジェットなど）を使用して、画面幅に合わせて自動的に折り返すように配置する。
  - 各単語ブロックの幅は、英単語と日本語訳のテキスト長に応じて動的に調整される。
  - 単語ブロック間の適切なマージンやパディング、フォントサイズなどは、コーディング時に適宜調整する。

5. スクロール処理:
  - 表示エリアが画面に収まらない場合、垂直スクロールが可能になるようにSingleChildScrollViewなどのウィジェットでラップする。

6. インタラクションの付与:
  - 各単語ブロックにタップジェスチャーリスナー（GestureDetectorなど）を付与する。
  - is_wordがtrueの場合にのみ、タップ時に辞書機能（VocabularyInputSheet）のシートを表示するトリガーとする。is_wordがfalse（句読点）の場合は、タップしても何も表示しない。

### 辞書データセットの選定

- **どの辞書データセットを使うか**: 内部辞書にはejdict-handを利用する。ejdict-handは、辞書データベース形式(SQLite)で提供されており、比較的簡単に利用できる。
- **ejdict-handの具体的な利用方法**: オフライン利用を可能にするため、ejdict-handのデータはアプリにローカルでダウンロードして組み込む。
- **辞書データの更新**: 内部辞書の更新は、とりあえず、アプリのアップデート時に新しい内部辞書ファイルに置き換える方法で行う。

## 単語帳・内部辞書の連携

### 単語帳データ (VocabularyEntry)

- データ管理: VocabularyEntryデータ構造に基づき、Sqfliteでデータの永続化を行う。
- CRUD操作:
  - Create (追加):
    - 「辞書機能」から、内部辞書の訳を単語帳に新規登録する。
    - 「オリジナル登録フィールド」から、ユーザーが入力した訳を単語帳に新規登録する。
  - Read (参照):
    - 翻訳モードの表示ロジックで優先的に参照される。
    - 単語帳モード画面でリスト表示される。
  - Update (更新):
    - 「オリジナル登録フィールド」から、「訳を非表示にするかどうか」のステータスやメモ、訳語自体を更新する。
    - 「辞書機能」画面で、既存の単語の訳やメモを編集する。
    - 単語ごとのis_hidden一意性保証: ある英単語に対して複数の訳語が登録されている場合、is_hiddenがfalse（表示）に設定できるのはそのうち一つのみとする。他の訳語のis_hiddenは自動的にtrue（非表示）に設定されるように、更新ロジックを実装する。
  - Delete (削除):
    - 「辞書機能」で、不要な単語エントリを削除する。
- 検索・フィルタ機能:
  - 単語帳モード画面に検索バーを設置し、英単語または日本語訳で絞り込み検索を可能にする。
  - フィルタオプション:
    - 訳を表示する単語のみ: is_hiddenがfalseの単語のみを表示。
    - 訳を非表示にする単語のみ: is_hiddenがtrueの単語のみを表示。

### 内部辞書データ (InternalDictionary)

- データ組み込み:
  - ejdict-handのSQLiteデータベースファイルを、アプリのアセット（例: assets/db/ejdict.sqlite3）としてプロジェクトに配置する。
  - アプリ起動時、または初回利用時に、以下の手順でこのデータベースファイルをアプリのプライベートストレージにコピーし、Sqfliteでアクセス可能にする。
    1. path_providerパッケージを使用して、アプリのドキュメントディレクトリ（getApplicationDocumentsDirectory()）のパスを取得する。
    2. コピー先のデータベースファイルのパス（例: [ドキュメントディレクトリ]/ejdict.sqlite3）を決定する。
    3. File(dbPath).exists()で、既にデータベースファイルが存在するかを確認する。
    4. 存在しない場合、rootBundle.load('assets/db/ejdict.sqlite3')でアセットからデータベースファイルをByteDataとして読み込む。
    5. 読み込んだByteDataをList<int>に変換し、File(dbPath).writeAsBytes()でコピー先のファイルに書き込む。
    6. openDatabase(dbPath)でデータベースを開き、以降の操作に利用する。
- 参照:
  - 辞書機能の訳語表示セクションで、候補訳として表示される。
- 更新:
  - アプリのアップデート時に、新しいバージョンのejdict-handデータベースファイルに置き換えることで更新を行う。  
  - 更新ロジックの例:
    1. アプリのバージョン情報（または辞書データのバージョン）をSharedPreferencesなどの永続ストレージに保存しておく。  
    2. アプリ起動時に、現在のアプリバージョン（またはアセット内の辞書バージョン）と保存されているバージョンを比較する。  
    3. 新しいバージョンが存在する場合、既存のデータベースファイル（File(dbPath).delete()）を削除する。  
    4. アセットから新しいデータベースファイルをコピーする（「データ組み込み」と同じ手順）。  
    5. SharedPreferencesの辞書バージョンを更新する。
