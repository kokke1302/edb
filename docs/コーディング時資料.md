# 英語学習支援アプリ 設計概要

このドキュメントは、英語学習支援アプリを開発するための主要な設計情報をまとめたものです。AIによる効率的なコーディングを目的とし、必要な情報を網羅的に整理しています。

## 1. アプリの目的とコンセプト

### 課題認識

既存の翻訳アプリが英文全体を日本語に変換するため、学生が英語を学ぶ上で重要な「単語の暗記」や「文法・文構造の理解」の機会を飛ばしてしまう可能性がある。

### 解決策

英文の各英単語の下に、対応する日本語の単語を併記して表示する。これにより、単語と単語の関係性を視覚的に理解し、英語の語順と日本語の語順の違いを把握する訓練を促す。

### 学習効果

- 単語レベルでの意味の対応関係を明確にする。
- 英語と日本語の語順の違いを視覚的に比較し、文構造の理解を助ける。
- ネイティブスピーカーのように左から右へ英文を読み進める訓練になる（返り読みの減少）。

### 独自性

「特定の英文に対し、単語ごとに日本語訳をその下に表示し、左から右へ読む訓練を主眼としたアプリ」という明確なコンセプトを持つ。

## 2. 開発フェーズと技術選定

### フェーズ

まず**主機能の実装のみ**の簡単なアプリを目指す（第1段階）。

- 第1段階: 主機能（基本的なUI/UX、テキスト処理、表示ロジック、辞書連携）
- 第2段階: ユーザー辞書/単語帳管理機能、英文の保存/履歴機能
- 第3段階: 外部API連携、同期処理

### 技術選定

- フロントエンド: Flutter（言語: Dart）- まずはモバイル（Android）で開発
- バックエンド: Flask（言語: Python）- 辞書データの提供やシンプルなテキスト処理、ユーザーデータの保存など（第3段階で導入）
- 状態管理: Riverpod (Flutter)
- ローカルデータベース: Drift (Flutter)

## 3. 機能一覧

### 主機能

1. 基本的なUI/UXデザイン: 見やすいレイアウト、英文入力インターフェース、要素配置。
2. 表示ロジック: 英文の長さや単語数に応じた表示調整、スクロール、改行処理、単語タップ時の詳細表示（辞書機能シート）など。
3. テキスト処理: 入力された英文を単語に分割（スペース分割、句読点処理）、小文字化、辞書検索キー生成、訳語割り当て。
4. 辞書データの連携と表示:
   - ユーザー辞書に登録された訳語を最優先で表示。
   - 未登録単語は内部辞書を参照して訳を提示。
   - 内部辞書からの訳をユーザー辞書に登録する選択肢を提供。
   - 英文保存機能。

### サブ機能（第2段階以降で実装）

- ユーザー辞書/単語帳管理機能（CRUD、検索、フィルタ）。
- 英文の保存/履歴機能。
- 音声読み上げ機能。
- ユーザー辞書の同期機能。
- 文脈に合わせた適切な訳語推薦ロジック。

## 4. UI/UX設計

### 全画面共通要素

- AppBar: 画面上部。ハンバーガーメニューアイコン（Leading）と現在の画面タイトル（Title）。
- Drawer: ハンバーガーメニューから開くサイドメニュー。ヘッダー「保存済みの英文」、保存された英文リスト（タップで復元、削除オプション付き）、設定、ヘルプ。
- BottomNavigationBar: 画面下部。翻訳モード、単語帳モードへの切り替えアイコン/ラベル。

### 翻訳モード画面

- 英文入力エリア: 画面上部、複数行TextField。薄いテキスト「タップでキーボードが起動します」。クリアボタン、ペーストボタンを左下に常設。
- 単語ブロック表示エリア: 画面下部。入力された英文を解析し、単語ごとに「単語ブロック」として表示。Wrapウィジェットで横並び・自動改行。上段に英単語、下段に日本語訳。ユーザー辞書からの訳語を表示。画面に収まらない場合は垂直スクロール。単語ブロックタップで「辞書機能シート」へ遷移。
- 右下FloatingActionButton: 「翻訳スタート」「英文保存」ボタン。

### 辞書機能シート（VocabularyInputSheet）

- 単語ブロックタップでshowModalBottomSheetで表示される。
- 英単語表示部: 英単語をTextで表示。
- 訳語表示セクション: 単語帳登録訳語と内部辞書訳語が対象。表示優先順位は「最優先訳語 > 単語帳登録訳語 > 内部辞書訳語」。各訳語の右に「訳を表示するかどうか」（Switch）と「単語帳へ登録済みかどうか」（Switch）を配置。登録済みの訳語にはメモも小さく表示。訳語がない場合はセクション非表示。
- オリジナル訳語セクション: 「オリジナル」と薄いテキスト表示。セクション全体がタップ可能で、「オリジナル登録フィールド」へ遷移。

### オリジナル登録フィールド（OriginalEntryScreen）

- オリジナル訳語を単語帳に登録・編集する画面。
- 英単語表示/入力フィールド: 単語帳入力画面から遷移時はTextで編集不可。単語帳モードから新規登録時はTextFieldで「英単語」と薄字。
- 訳語入力フィールド: TextField、「オリジナル」と薄字。
- メモ入力フィールド: TextField、「メモ」と薄字。
- 訳の表示可否スイッチ: Switch、初期状態はoff（false）。
- 操作ボタン: 「保存」「キャンセル」。

### 単語帳モード画面

- 上部: フィルタボタンと検索ボタンを横並びに配置。
- データベース部:
  - 最上部にIconButton形式の+ボタン。タップで「オリジナル登録フィールド」へ遷移。
  - その下に、右に英語、左に訳語が表示されるカラム形式で単語リストをListViewで表示。
- 右下FloatingActionButton: フィルタ、検索、新規単語登録のショートカットボタン。

## 5. データ構造設計

### 英文データ構造（EnglishTextData）

アプリ内部で英文を管理するためのデータ構造。Sqfliteで管理。

| フィールド名 | 型 | 説明 |
| :---- | :---- | :---- |
| id | INTEGER | 主キー、自動インクリメント |
| original_text | TEXT | 元の英文全体 |
| parsed_words_json | TEXT | 解析された単語のリスト（JSON形式で保存） |
| created_at | TEXT | 保存日時 |
| updated_at | TEXT | 更新日時 |

parsed_words_jsonの内部構造例（トークン配列）:

```json
[
  {
    "word": "I",
    "lookup_key": "i",
    "resolved_translation": "私", // 最終的に表示される訳語。単語帳設定で非表示なら空文字列
    "is_word": true // 単語である場合はtrue
  },
  {
    "word": ".",
    "lookup_key": null,
    "resolved_translation": null,
    "is_word": false // 句読点であるためfalse
  }
]
```

### 単語帳データ構造（VocabularyEntry）

ユーザーが独自に登録した単語と訳を管理するためのデータ構造。Sqfliteで管理。

| フィールド名 | 型 | 説明 |
| :---- | :---- | :---- |
| id | INTEGER | 主キー、自動インクリメント |
| english_word | TEXT | 英単語（小文字で保存、ユニーク制約） |
| japanese_translation | TEXT | 日本語訳 |
| is_hidden | INTEGER | 訳を非表示にするかどうか (0: false, 1: true) |
| memo | TEXT | ユーザーメモ |
| created_at | TEXT | 登録日時 |
| updated_at | TEXT | 更新日時 |

### 内部辞書データ構造（InternalDictionary）

ejdict-handのデータをアプリに組み込む際のデータ構造。Sqfliteで管理。

| フィールド名 | 型 | 説明 |
| :---- | :---- | :---- |
| id | INTEGER | 主キー |
| word | TEXT | 英単語（小文字で保存） |
| translation | TEXT | 日本語訳 |

## 6. テキスト処理ロジック

1. 入力英文の取得: ユーザーが入力した英文（String）を取得。
2. 文の分割: ピリオド (.)、疑問符 (?)、感嘆符 (!) のいずれかの後に、アルファベット以外の文字が続く箇所で文に分割する。
   - 例: "Hello. How are you?" -> ["Hello.", " How are you?"]
   - DartのStringクラスと正規表現を使用。
3. 各文のトークン配列生成:
   - スペースと主要な句読点（., ,, !, ?, :, ;, ", ', (, ), [, ]など）で文字列を分割し、単語と句読点を独立したトークンとして扱う。
   - ハイフンやアポストロフィを含む単語（例: don't, well-known）は分割せず1つの単語として扱う。
   - 各トークンに対し、is_word属性を設定（単語ならtrue、句読点ならfalse）。
   - DartのStringクラスと正規表現を使用。
4. 小文字化と辞書検索キー生成:
   - is_word: trueの単語トークンのみ、全て小文字に変換したものをlookup_keyとする。
   - is_word: falseの句読点トークンは、lookup_keyをnullとする。
   - 例: "Hello" -> lookup_key: "hello"
5. トークンへの訳語割り当てフロー:
   - 各単語トークン（is_word: true）に対し、辞書検索キー（lookup_key）を用いて単語帳（VocabularyEntry）を検索する。
     - 見つかった場合: is_hiddenがtrueならresolved_translationは空文字列""。is_hiddenがfalseならjapanese_translationをresolved_translationに格納。
     - 見つからなかった場合: resolved_translationは空文字列""。
6. 英文データ構造への変換: 上記処理で得られた各トークン情報をEnglishTextDataのparsed_words_jsonフィールドに格納する形式に変換する。

## 7. 表示ロジック設計

1. 英文データの取得: 翻訳モードで表示すべきEnglishTextDataを取得。
2. 単語ブロックの生成: parsed_words_jsonをパースし、各トークンに対して「単語ブロック」ウィジェットを生成。
3. 訳語の表示:
   - 各単語ブロック生成時、トークンのresolved_translationを参照。
   - is_word: trueかつresolved_translationがnullまたは空文字列でなければ、その値を単語ブロックの下段に表示。
   - 句読点（is_word: false）の場合は訳語を表示しない。
4. レイアウト調整: Wrapウィジェットを使用し、画面幅に合わせて自動折り返し。単語ブロックの幅は英単語と日本語訳のテキスト長に応じて動的に調整。
5. スクロール処理: 表示エリアが画面に収まらない場合、SingleChildScrollViewで垂直スクロール可能にする。
6. インタラクションの付与: 各単語ブロックにGestureDetectorを付与。is_word: trueの場合にのみ、タップ時に辞書機能シート（VocabularyInputSheet）を表示するトリガーとする。

## 8. 単語帳・内部辞書の連携

### 単語帳データ（VocabularyEntry）

- 管理: Sqfliteでデータの永続化。
- CRUD操作:
  - Create: 辞書機能シート、オリジナル登録フィールドから新規登録。
  - Read: 翻訳モード表示ロジックで優先参照、単語帳モード画面でリスト表示。
  - Update: オリジナル登録フィールド、辞書機能シートから更新。
    - is_hidden一意性保証: ある英単語に対し複数の訳語が登録されている場合、is_hidden: false（表示）に設定できるのはそのうち1つのみ。他の訳語のis_hiddenは自動的にtrue（非表示）に更新するロジックを実装。
  - Delete: 辞書機能シート、単語帳モード画面から削除。
- 検索・フィルタ機能: 単語帳モード画面に検索バー。英単語または日本語訳で絞り込み。フィルタオプション（訳を表示する単語のみ、訳を非表示にする単語のみ）。

### 内部辞書データ（InternalDictionary）

- 採用辞書: English-Japanese Dictionary "ejdict-hand"（SQLite形式）。
- データ組み込み:
  1. アプリのアセット（assets/db/ejdict.sqlite3）として配置。
  2. アプリ起動時または初回利用時に、path_providerで取得したアプリのプライベートストレージにファイルをコピーし、Sqfliteでアクセス可能にする。
- 参照: 辞書機能シートの訳語表示セクションで候補訳として表示。
- 更新: アプリのアップデート時に、新しいバージョンのejdict-handファイルに置き換える。バージョン情報（SharedPreferencesなど）を比較し、新しいバージョンがあれば既存ファイルを削除し、新ファイルをコピーする。

## 9. イベントハンドラ

主要なイベントと動作フローを以下にまとめます。

### 単語ブロックのタップ

1. 検知: GestureDetectorまたはInkWellがタップを検知。句読点など単語でないブロックは無視。
2. 特定: タップされた単語ブロックに対応する英単語（word.lookup_key）を特定。
3. データ取得: DictionaryServiceやVocabularyRepositoryの非同期関数（例: fetchWordTranslations(tappedWord)）を呼び出し。
4. データベース問い合わせ: Sqfliteデータベースに対し、VocabularyEntryテーブルとInternalDictionaryテーブルをクエリ。
5. レスポンス処理: Futureオブジェクトをawaitで待機。生データ（Mapのリスト）をアプリケーションのデータモデルにパース。
6. データ結合・ソート: ユーザー辞書と内部辞書からの結果を結合し、表示優先順位に従ってソート。
7. UI更新: 取得・パース・結合された訳語データをRiverpodを通じてUIに提供。
8. シート表示: showModalBottomSheet関数で辞書機能シート（VocabularyInputSheet）を表示。

### 訳語の「訳を表示するかどうか」スイッチの切り替え

1. 検知: スイッチ操作を検知。
2. 排他制御ロジック:
   - 「表示」（is_hidden: false）に切り替えた場合: 同じ英単語に紐づく他のすべての訳語のis_hiddenを自動的に「非表示」（is_hidden: true）に更新。その後、選択した訳語のis_hiddenを「表示」（is_hidden: false）に更新。
   - 「非表示」（is_hidden: true）に切り替えた場合: その特定の訳語のis_hiddenのみを「非表示」（is_hidden: true）に更新。
3. データベース更新: 上記排他制御ロジック適用後、変更された訳語の状態をSqfliteに保存。データ整合性のため**トランザクション**として実行。

### 「オリジナル」セクションのタップ、または単語帳モード画面での新規登録ボタンのタップ

1. 検知: タップイベントを検知。
2. 画面遷移: オリジナル登録フィールド（OriginalEntryScreen）へ画面遷移。辞書機能シートから遷移した場合は、タップされた英単語が遷移先に引き渡される。

### オリジナル登録フィールドでの保存ボタンのタップ

1. 検知: 「保存」ボタンのタップを検知。
2. 取得と検証: 各入力フィールドから値を取得し、入力検証。
3. データベース更新: ユーザー辞書（VocabularyEntry）に新規登録または既存の訳語を更新。この際、訳語の「訳を表示するかどうか」スイッチの状態に基づき、前述の「訳語の表示設定変更時のフロー」と同様の排他制御ロジックが適用。
4. 画面クローズ: 保存処理完了後、画面が閉じられ、前の画面に戻る。

### 単語エントリの削除操作

1. 検知: 削除アイコンタップ、または削除オプション選択を検知。
2. 確認ダイアログ: 誤操作防止のため「本当に削除しますか？」という確認ダイアログを表示。

### 削除確認ダイアログでの承認

1. 検知: 確認ダイアログで削除の承認ボタンをタップ。
2. データベースからの削除: 該当する単語エントリをSqfliteから削除。
3. UI更新: 削除完了後、単語帳リストや辞書機能シートの表示を更新。

## 10. エラーハンドリングと例外処理

### エラーの種類と対応

- 入力値エラー: 空の英文入力、無効な文字など。
  - メッセージ: 「英文を入力してください。」などUIに表示。
  - 動作: 処理中断、修正を促す。
- ハードウェアリソースのオーバーフロー: ストレージ不足、メモリ不足。
  - メッセージ: 「ストレージ容量が不足しています。」など警告メッセージ。
  - 動作: ストレージ不足時は保存中止、他の機能は継続。メモリ不足時は警告表示、可能な範囲で処理継続（例: 表示件数制限）。クラッシュは避ける。
- レンダリングエラー: UIレイアウトのオーバーフロー、パフォーマンス低下。
  - メッセージ: 通常表示しない。
  - 動作: テキスト折り返し、省略記号（...）、スクロール可能領域提供、リストビューの仮想化などで対応。
- 関数の例外（ロジックエラー・データ破損など）: クリップボードからの予期せぬ文字コード、データファイル破損、辞書検索エラー。
  - メッセージ: 「予期せぬエラーが発生しました。」など。
  - 動作: try-catchで捕捉しクラッシュ防止。致命的エラー時は再起動/再インストールを促す。非致命的エラー時はログ記録、「訳語なし」表示などで処理継続。

### エラーハンドリングメカニズム

- try-catchブロック: Dartのtry-catchを積極的に使用。
- 非同期処理: FutureのcatchErrorやasync/awaitとtry-catchを組み合わせ。
- カスタム例外クラス: AppException, DataException, DictionaryExceptionなどを定義し、エラーの種類を明確化。
- ユーティリティ関数: handleAppErrorなどの共通関数を作成し、UI通知（SnackBarやDialog）、ログ出力を一元化。

## 11. パフォーマンス要件

- 起動時間: 3秒以内。
- 翻訳処理速度: 短い英文（20単語程度）1秒以内、長い英文（200単語程度）3秒以内。
- UIの応答性: 常にスムーズで遅延がないこと。
- 辞書検索速度: 0.1秒以内。
- データ保存・読み込み速度: 少量データ0.5秒以内、大量データ2秒以内。
- メモリ使用量: 一般的なモバイルアプリの基準値内。
- バッテリー消費: 一般的なアプリと同等レベル。

## 12. セキュリティ要件

- データ保存のセキュリティ: ローカルデータベース（Sqflite）のデータはデバイスのプライベートストレージに保存。
- 入力値の検証: 不正なデータや悪意のあるコードの挿入を防ぐため、常に検証。
- 将来的なAPI連携時: HTTPS（SSL/TLS）による通信暗号化、認証情報の安全な管理（Android KeyStoreなど）、APIキーの安全な管理、ユーザー認証・認可の仕組み（第3段階で検討）。

### 目的と範囲

主機能が意図通りに動作するか、UI/UXが使いやすいか、パフォーマンス要件を満たしているか、エラーハンドリングが適切かを確認。

### テストの種類と戦略

- 単体テスト (Unit Test): 最小単位（関数、メソッド、クラス）の検証。Flutterのtestパッケージで自動化。
- ウィジェットテスト (Widget Test): UIコンポーネントのレンダリングとインタラクション検証。Flutterのflutter_testパッケージでシミュレート。
- 結合テスト (Integration Test): 複数コンポーネント連携動作の検証。Flutterのintegration_testパッケージでエンドツーエンドの動作確認。
- パフォーマンステスト (Performance Test): 起動時間、翻訳処理速度、メモリ使用量などの検証。Flutter DevToolsなどでプロファイリング。
- エラーハンドリングテスト (Error Handling Test): エラーシナリオ（ストレージ不足、不正入力、データ破損）に対するアプリの挙動検証。
- 受け入れテスト (Acceptance Test): ユーザー視点でのビジネス要件、期待値の確認。開発者および協力者による手動テスト。

### テスト環境

- 開発環境: 開発者のPC（エミュレータ/シミュレータ含む）。
- 実機: 数種類のAndroid実機（異なるOSバージョン、画面サイズ）でテスト。
- テストデータ: 通常/異常な英文、単語帳データ、破損データなど多様なパターンを用意。
